# 모바일 러너 연결과 디스플레이

> 연결·좌표·복구 절차와 검증 범위를 설명한다.

## 검증한 경로

- Mac CLI → Xcode의 기존 paired IPv6 tunnel → 실기기의 DeviceKit XCTest 서버 → JSON-RPC 네이티브 액션. 관찰자는 `/mjpeg` 기기 프레임을 ffmpeg로 저장한다. Mobile MCP의 실기기 탐색이나 Device Hub는 의존성이 아니다.

- 2026-11-13 기존 페어링된 iOS 27.3 실기기를 Wi-Fi·펼친 상태로 실행했다. 모드 선택 → 클래스 → 앱 이전 페이지로 복귀, Safari 주소창의 한글 키보드 `ㄱ·ㅏ·ㄴ·ㅏ` 직접 탭 → focused value `가나` → 편집 취소를 확인했다. 앞서 시도한 문자열 주입은 키보드 UI 통과 근거에서 제외했다. 앱 본문 입력·모든 키보드·삭제·전송·스크롤까지 검증한 것은 아니다.

## 기존 빌드와 다중 화면 보정

- 유효한 서명 설정으로 build-for-testing한 DeviceKit `.xctestrun`과 Runner.app이 필요하다. 팀·번들 식별자·프로비저닝 값은 현재 환경에서 확인한다. 스킬은 인증서·프로파일·기기 권한을 설치하거나 갱신하지 않는다. 테스트·빌드는 `atest run -- ...`으로 감싼다.

- 보정은 DeviceKit 로컬 기준 HEAD `929cc67`의 `DeviceKitTests/JSONRPC/Handlers/IOTap.swift` 대상이다. 다른 버전은 소스를 먼저 비교한다. 해당 버전의 OrientationGeometry와 EventRecord는 displayID 생성자를 이미 갖고 있었다.

```bash
git -C "$DEVICEKIT_SOURCE" apply --check "$SKILL/assets/devicekit-display-tap.patch"
git -C "$DEVICEKIT_SOURCE" apply "$SKILL/assets/devicekit-display-tap.patch"
```

- 보정은 tap 요청에 displayID·nativeCoordinates·dryRun을 추가하고 선택 display·실행 여부를 응답한다. 명시적 display 타기팅이 불가능하면 실패한다. 보정 후 기존 서명을 보존해 다시 build-for-testing한다. 이미 적용되어 있으면 재적용하지 않는다. 필요한 경우에만 수행한다.

## 실행과 복구

1. `xcrun devicectl list devices`와 `device info details --device ... --json-output <임시파일>`로 대상과 paired·connected·localNetwork 여부를 읽는다.
2. launch_runner.py는 시작 직전 connectionProperties.tunnelIPAddress를 읽고 `TEST_RUNNER_DEVICEKIT_LISTEN_HOST=127.0.0.1,<paired-tunnel>`을 구성한다. 전체 네트워크에 바인딩하지 않는다.
3. xcodebuild test-without-building을 atest로 실행한다. 터미널 세션을 유지하고 ready 로그와 `GET /health`의 OK를 확인한다.
4. mobile_record.py init으로 붙는다. 실행마다 새 run 디렉터리를 쓴다. 터널과 기기 정보는 로컬 산출물에만 남긴다.
5. 자신의 러너만 `POST /shutdown`으로 종료한다. Python urllib.request.Request(endpoint + '/shutdown', data=b'', method='POST')를 프록시 없는 opener로 보낼 수 있다. XCTest 종료 코드를 확인한다.

- `Bind(49): Can't assign requested address`면 준비와 실행 사이 tunnel 변경을 확인한다. 실패한 실행 종료를 확인하고 최신 details로 한 번 다시 시작한다. 무한 재시도하지 않는다. 기기에 Enable UI Automation 생체 인증이 뜨면 사용자 조작이 필요하다. 다른 권한을 바꾸거나 데스크톱 조작으로 우회하지 않는다.

## 화면과 좌표

- devicectl의 device info displays JSON에서 active를 고른다. 기본 primary가 꺼진 커버 화면일 수 있다.

- displayId는 네이티브 이벤트 대상이며 raw AX window.displayID와 대조한다.
- uniqueId는 devicectl screenshot의 --display-unique-id 대상이다.
- pointScale은 화면 픽셀을 터치 point로 바꿀 때 쓴다.
- AX window 원점은 음수일 수 있다. 터치 중심은 `(element.X + Width/2 - window.X, element.Y + Height/2 - window.Y)`다.
- screenshot과 MJPEG의 회전이 다를 수 있다. 스트림 첫 프레임을 별도 추출해 방향을 확인한다. fps는 목표값이다.

- 검은 캡처 하나로 잠금 상태라고 단정하지 않는다. 활성 display의 devicectl screenshot, DeviceKit screenshot, foreground, raw AX를 함께 본다. 접힘·회전 후 모든 좌표를 폐기한다.

## 실패 분류

- 탭 success는 이벤트 합성 요청의 성공일 뿐 전환의 증거가 아니다. foreground 변경이나 잘못된 display면 화면이 그대로일 수 있다. device.apps.foreground에는 fields: []로 불필요한 상세 조회를 피한다.

- 탐색·터널·서명·자동화 인증·녹화 실패는 인프라 실패로 기록한다. 앱 기대 상태 미확인과 구분한다. UI 스냅샷과 프레임은 원자적으로 동기화되지 않으며 수집 중 영상이 멈출 수 있다. 단일 기기를 병렬 제어하지 않는다.
