# 에뮬레이터 실측과 녹화

> iOS 시뮬레이터·Android 에뮬레이터, 그리고 Android 실기기(`adb -s <serial>`)에서 화면을 조작·녹화하는 경로다. 비어 있는 실기기가 없을 때 시뮬레이터·에뮬레이터를 쓴다.

## 언제 에뮬레이터, 언제 실기기

- **비어 있는 실기기가 먼저다.** `scripts/free_devices.py`로 연결된 실기기의 점유를 확인하고, `"free": true`인 기기가 있으면 그 기기를 쓴다. 다른 세션이 쓰는 기기는 건드리지 않는다.
- 비어 있는 실기기가 없을 때만 iOS 시뮬레이터·Android 에뮬레이터를 쓴다. 최종 보고에 실기기를 못 쓴 이유(전부 사용 중·미연결)를 적는다.
- 카메라·마이크·푸시·생체 인증, 접이식·다중 화면, 실제 네트워크·성능처럼 실기기에서만 재현되는 확인인데 실기기가 모두 사용 중이면 에뮬레이터로 대신하지 말고 사용자에게 묻는다. 마이크(스피킹) 단계는 실기기라도 스피커로 음원을 틀지 않는다 — SKILL.md 의 「음성 입력」 절을 따른다.
- Android 실기기는 아래 Android 절의 명령을 `adb -s <serial>`로 그대로 쓴다. 쓰는 동안 `python3 "$SKILL/scripts/free_devices.py" --hold <serial>`(또는 대기열로 받은 `--acquire` 터미널)을 별도 터미널 세션에 띄워 두고, 끝나면 `q`로 푼다.
- Mobile MCP는 쓰지 않는다.
- `scripts/`의 러너·관찰자·시나리오 실행기는 devicectl 기반이라 iOS 실기기 전용이다. 에뮬레이터는 아래 플랫폼 CLI를 직접 쓴다. 단계 진행은 똑같이 **관찰 → 동작 → 재관찰 → 판정**이고 `atest start --kind manual` → `atest case` → `atest end`로 기록한다.

## iOS 시뮬레이터 (`xcrun simctl`)

```bash
xcrun simctl list devices booted                      # 대상 UDID 확인, 없으면 boot
xcrun simctl boot "$UDID" && open -a Simulator
xcrun simctl install "$UDID" "$APP_PATH"              # 시뮬레이터용 빌드(.app)
xcrun simctl launch "$UDID" "$BUNDLE_ID"
xcrun simctl openurl "$UDID" "$URL"
xcrun simctl io "$UDID" screenshot "$RUN/before.png"
```

- 녹화: `xcrun simctl io "$UDID" recordVideo --codec=h264 --force "$RUN/video.mp4"`를 별도 터미널 세션에서 띄우고, 끝낼 때 SIGINT(Ctrl-C)를 보낸다. SIGKILL은 파일을 마감하지 못한다.
- 화면이 바뀔 때만 프레임을 쓰므로, 화면이 멈춰 있으면 영상 길이가 실제 경과 시간보다 짧다(2026-11-16 정지 화면 3초 녹화 → 0.07초). 길이로 경과 시간을 판정하지 않는다.
- 끝나면 `ffmpeg -v error -i video.mp4 -f null -`로 전체 디코딩을 확인하고 head/tail 프레임을 추출해 직접 본다.
- **탭·키 입력:** simctl에는 탭 명령이 없다. 네이티브 탭은 시뮬레이터용으로 build-for-testing한 XCUITest 러너(DeviceKit 포함)를 `-destination 'platform=iOS Simulator,id=$UDID'`로 띄워야 한다. 이 경로는 아직 실측하지 않았다. 처음 쓸 때 검증 결과를 이 문서에 남긴다. Mac GUI 클릭으로 대신하지 않는다.
- 웹 앱 확인은 시뮬레이터 Safari를 `openurl`로 열 수 있다.

## Android 에뮬레이터 (`adb`)

SDK 위치는 보통 `~/Library/Android/sdk`이고 `emulator`·`adb`가 PATH에 없을 수 있다.

```bash
SDK=~/Library/Android/sdk
"$SDK/emulator/emulator" -list-avds
"$SDK/emulator/emulator" -avd "$AVD" -no-snapshot-save &   # 터미널 세션으로 유지
"$SDK/platform-tools/adb" wait-for-device
"$SDK/platform-tools/adb" shell getprop sys.boot_completed  # 1 이 될 때까지 대기
adb install -r "$APK"
adb shell am start -n "$PACKAGE/$ACTIVITY"                  # 또는 am start -a android.intent.action.VIEW -d "$URL"
adb exec-out screencap -p > "$RUN/before.png"
adb shell uiautomator dump /sdcard/ui.xml && adb pull /sdcard/ui.xml "$RUN/ui.xml"
adb shell input tap "$X" "$Y"                               # 픽셀 좌표, uiautomator bounds 중심
```

- 좌표는 최신 `uiautomator dump`의 `bounds`에서 중심을 구한다. 회전·키보드 표시 후에는 다시 덤프한다.
- 녹화: `adb shell screenrecord --bit-rate 4000000 /sdcard/run.mp4` (최대 3분, 길면 나눠 찍는다) → SIGINT로 멈춘 뒤 `adb pull`한다.
- **키보드 검증:** `adb shell input text`는 문자열 주입이라 키보드 UI 통과 근거가 아니다. 화면 키보드 키를 `input tap`으로 하나씩 누른다. 키보드 키가 uiautomator 트리에 안 나오면 스크린샷에서 키 위치를 골라 누르고, 매 키 후 캡처로 입력값을 확인한다.
- 이 Android 경로는 아직 실측하지 않았다. 처음 쓸 때 검증 결과를 이 문서에 남긴다.

## 산출물

- 실기기와 같은 run 폴더 구조(스크린샷, 영상, 판정 메모)를 쓴다. 최종 보고에는 **에뮬레이터 이름·OS 버전**과 "실기기 미검증"인 항목을 명시한다.
